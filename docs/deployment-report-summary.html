01

Problem Statement & Solution Overview

Commercial off-the-shelf automated dubbing tools fail when applied to children's animation: they flatten expressive character personalities into a single generic narrator, produce clumsy literal machine translations that lack kid-friendly warmth, and ignore strict regional cultural taboos across JAPAC countries (Vietnam, Indonesia, Japan, etc.).

XIVI re-engineers localization into a Collaborative Multi-Agent Pipeline with Google Gemini as the central intelligence engine (no custom CV/NLP models are trained):

🎭

Series-Wide Voice Consistency

Every character receives a persistent character_id and acoustic profile stored in PostgreSQL, backed by Gemini 3.8 Flash Voice Design and native audio prebuilt voices so voices never drift across episodes.

🌏

Contextual Kids Localization

Dialogue avoids clumsy, literal machine translation. Specialized prompts instruct Gemini to adapt humor, child-friendly idioms, and natural conversational cadence appropriate for young audiences in target languages.

🛡️

Dynamic Cultural Safety Guardrails

Dialogue is screened against extensible database rules (cultural_safety_rules table) per target country; outputs severity scores (Safe, Low, Medium, High) with natural-language rationales for human reviewers.

📚

Bilingual Learning & Quiz Generation

Agent 7 asynchronously extracts 8–12 age-appropriate vocabulary flashcards and interactive multiple-choice quiz questions from the dubbed dialogue, transforming entertaining cartoons into learning materials.

🎬

Canva-Style In-Browser Timeline Editor

An integrated multi-track WaveSurfer.js waveform editor enables visual lip-sync adjustments, audio trimming, volume balancing, and server-side non-destructive FFmpeg remuxing.

⚡

Script-First Parallel Workflow

Allows translation and dubbing to begin immediately from locked scripts (CSV/text) using AI duration benchmarks, unlocking parallel localization weeks before final animated footage is rendered.

Mandatory Ethical Principle: No AI agent is permitted to auto-publish content destined for young audiences. Every episode must pass an explicit Human Review Gate in the studio dashboard before release.
02

Leveraging Firebase, Cloud Firestore & Cloud Run

The platform embraces Google Cloud's Serverless Managed Services to maximize developer velocity, eliminate server maintenance, and ensure instant realtime responsiveness:

🌐

1. Firebase Hosting & Firebase Auth

• Global Edge CDN: Distributes the compiled React 18 SPA across Google's worldwide edge caches with single-page rewrite rules (** -> /index.html).
• Secure Authentication: Verifies user identity via Firebase Auth JWT ID tokens validated server-side using firebase_admin.auth.verify_id_token.

🔥

2. Cloud Firestore (Realtime State Streaming)

• Zero-WebSocket Streaming: The client dashboard uses Firestore's client-side onSnapshot listener to receive instant pipeline stage transitions and progress percentages (0%–100%).
• Separation of Concerns: Firestore exclusively handles ephemeral execution progress. All transactional business data, permissions, and dialogue lines reside safely in PostgreSQL.

🚀

3. Google Cloud Run (Decoupled Services)

• API Orchestrator (toonlingo-api): Scales rapidly from 0 to 10 instances (scale-to-zero), delivering sub-50ms HTTP responses and issuing signed upload URLs.
• Worker Container (toonlingo-worker): Allocated 2 vCPU, 2 GiB RAM, timeout of 3600s, and concurrency=1 to guarantee CPU-intensive FFmpeg tasks never suffer OOM errors.

Fault-Tolerant Checkpoint & Resume Guarantee

To protect against container preemption or temporary network blips during multi-minute dubbing runs, the worker writes a transactional checkpoint to the jobs.current_stage column in PostgreSQL before each state transition:

Automatic Resume Guarantee: If a worker container restarts during step 5 (Dubbing), Pub/Sub redelivers the event. The worker reads current_stage = "safety_checked" and immediately resumes dubbing — skipping Ingestion, Voice Profiling, and Translation to eliminate duplicate Gemini API costs.
03

The 7-Stage Agent Pipeline & Google Gemini Integration

All model interactions are centralized inside the singleton service backend/worker/services/gemini_client.py to enforce rate limiting, exponential backoff, and Redis hash caching:

Agent / Stage Primary Input Output Artifact Gemini Model Utilized
1. Ingestion Agent Audio stream stripped from source video Dialogue transcript, sub-second timestamps, speaker diarization gemini-3.6-flash (Multimodal Audio)
2. Voice Profiling Sample voice clips + character description Assigned character_id, matched registry profile or newly synthesized voice gemini-3.8-flash-tts / Prebuilt Voices
3. Translation Agent Dialogue lines + target language code Contextual, age-appropriate localization preserving character humor and warmth gemini-3.6-flash (Contextual Mode)
4. Cultural Safety Localized text + database rules per country Safety status (safe/flagged), severity level, natural-language rationale gemini-3.6-flash (Reasoning Mode)
5. Dubbing Synthesis Approved translated lines + character voice ID Synthesized speech clips aligned to dialogue timestamp windows gemini-3.1-flash-tts-preview (Native Audio)
6. Muxing Engine Dubbed audio clips + original video stream Separates BGM, stitches dubbed speech, encodes faststart MP4 FFmpeg Engine (C Service)
7. Educational Content Full translated episode transcript 8–12 bilingual vocabulary flashcards and interactive multiple-choice quiz questions gemini-3.6-flash (Structured JSON Mode)

3-Tier Fallback Hierarchy for Character Voice Synthesis

Guarantees that voice assignment never breaks the pipeline execution:

  • Tier 1 — Gemini 3.8 Voice Design: Synthesizes a bespoke voice from personality prompts using client.voices.create(type="prompted"). If Google's safety filter flags the generated voice (e.g. sounding like a minor), the system gracefully degrades to Tier 2.
  • Tier 2 — Prebuilt Native Voices: Matches against Gemini's 12 prebuilt voices based on character gender, pitch, and energy attributes.
  • Tier 3 — Deterministic Hash Fallback: Applies hash(character_id) % 12, guaranteeing that the same character consistently speaks with the exact same voice across all episodes.
04

Two Workflow Breakthroughs: Timeline Editor & Script-First

🎬 In-Browser Timeline Editor (Spec 002)

• Instant Feedback: Local Zustand state and WaveSurfer.js render audio waveforms directly in the browser for sub-100ms UI response.
• Resilient Autosave: Automatically debounces user edits for 3 seconds before writing a single JSONB document to jobs.timeline_edits in PostgreSQL.
• Non-Destructive Server Export: Clicking "Export Video" compiles an FFmpeg filter_complex script that renders adjusted volume gains, cuts, and offsets into a pristine MP4 file without altering original source media.

⚡ Script-First Parallel Ingestion (Spec 003)

• Parallel Production: Animation studios no longer wait for final video renders; locked scripts (CSV/text) can be translated and dubbed weeks ahead.
• AI Duration Benchmarking: The ScriptBenchmarkAgent generates reference audio to calculate natural dialogue timing boundaries.
• Late Video Attachment: Once final animation cuts are delivered, calling POST /jobs/{id}/attach-video maps pre-dubbed audio directly to the video, skipping redundant Gemini processing.
