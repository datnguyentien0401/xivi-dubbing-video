XIVI Studio ARCHITECTURE SUMMARY

Executive Solution & Infrastructure Summary

A focused architectural overview of XIVI Studio — an agentic localization pipeline for kids' animation across JAPAC languages, using Google Gemini as the core intelligence engine, orchestrated via Firebase, Firestore, Cloud Run, Pub/Sub, and Redis.

Live Web App API Swagger Docs
01. SOLUTION

Problem Statement & Autonomous Agentic Solution

Standard AI dubbing tools fail when applied to children's animation: they flatten expressive characters into a single generic narrator, produce literal translations that lack kid-friendly warmth, and ignore strict regional cultural taboos across JAPAC markets.

🎭

Series-Wide Voice Consistency

Each character is assigned a persistent character_id in PostgreSQL. Timbre and pitch are preserved using Gemini 3.8 Flash Voice Design and native audio prebuilt voices so character voices never drift across episodes.

🌏

Contextual Kids Localization & Safety

Dialogue is translated with age-appropriate humor and warmth, then screened against extensible cultural safety rules in PostgreSQL with natural-language rationales. No agent is permitted to auto-publish without human review.

03. INFRASTRUCTURE DEEP-DIVE

Leveraging Firebase, Firestore, Cloud Run, Pub/Sub, Redis & Gemini

🌐

1. Firebase Hosting & Firebase Auth

• Global Edge CDN: Distributes the compiled React 18 SPA bundle across Google's worldwide POPs with single-page rewrite rules (** -> /index.html) for instantaneous load times.
• Token-Based Auth: Authenticates creators via Google OAuth and issues JWT ID tokens verified server-side on every API request via firebase_admin.auth.verify_id_token.

🔥

2. Cloud Firestore (Realtime State Streaming)

• Zero-WebSocket Streaming: The client dashboard uses Firestore's client-side onSnapshot listener to receive live pipeline stage transitions and progress percentages (0% to 100%) without maintaining WebSocket server clusters.
• Separation of Concerns: Firestore exclusively stores ephemeral runtime progress. Core transactional data, permissions, and dialogue lines reside safely in PostgreSQL.

🚀

3. Google Cloud Run (Decoupled Microservices)

• API Service (api): Lightweight, fast-scaling (0–10 instances) HTTP gateway handling CRUD, signed upload URLs, and job triggering with sub-50ms latency.
• Worker Service (worker): Allocated 2 vCPU, 2 GiB RAM, 3600s timeout, and concurrency=1 to guarantee CPU-intensive FFmpeg audio/video remuxing runs in complete isolation.
• Cloud Run Jobs: Runs short-lived alembic upgrade head migrations deterministically before new service revisions accept traffic.

📨

4. Cloud Pub/Sub (Event Streaming & Decoupling)

• Asynchronous Decoupling: The API publishes events ({"type": "job", "job_id": "..."}) and immediately returns 202 Accepted, freeing HTTP threads from blocking on long tasks.
• Secured Push Subscriptions: Cloud Pub/Sub delivers messages to private worker endpoints using Google IAM OIDC Identity Tokens, verified against PUBSUB_PUSH_AUDIENCE.

⚡

5. Redis (Distributed Locking & Gemini Cache)

• Distributed Locks: Manages pubsub_lock:{job_id} (TTL 1800s) to prevent duplicate execution during Pub/Sub redeliveries or concurrent race conditions.
• Gemini Result Caching: Caches translation responses under translate:{hash}:{lang} with a 24-hour TTL, saving substantial API quota and reducing latency on repeated phrases.

🧠

6. Google Gemini AI Core (Multi-Model Pipeline)

• gemini-3.6-flash: Powers transcription diarization, contextual translation, cultural safety assessment with reasoning, and bilingual vocabulary/quiz generation.
• gemini-3.1-flash-tts-preview: Synthesizes expressive native audio speech matching original dialogue timing.
• gemini-3.8-flash-tts: Designs bespoke character voices directly from personality descriptions.
• 3-Tier Fallback: Voice Design ➔ 12 Prebuilt Native Voices ➔ Deterministic Hash Fallback ensures zero dubbing pipeline failures.
